# План тестування: додавання Audi TT до Garage гостем

## Мета та межі

Перевірити через UI, що гість може додати автомобіль Audi TT із пробігом 12000 до Garage. Не використовувати API.

## Джерело вимог

`requirements/add_Audi_car.md`

## Сценарій: гість додає Audi TT

### Початковий стан

- Відкрито QAuto за адресою `https://qauto.forstudy.space/`.
- Користувач увійшов через `Guest log in`.
- Відкрито розділ `Garage`.

Цей стан взято з вимоги. Інструкція планувальника про «порожній/свіжий стан» не узгоджується з нею; початковий стан потрібно уточнити перед автоматизацією, якщо він впливає на сценарій.

### Кроки та очікувані результати

1. Натиснути `Add car`.
   - Очікувано: відкрилася форма додавання автомобіля.
2. У полі Brand вибрати `Audi`.
   - Очікувано: вибрано бренд Audi.
3. У полі Model вибрати `TT`.
   - Очікувано: вибрано модель TT.
4. У полі Mileage ввести `12000`.
   - Очікувано: поле містить значення 12000.
5. Натиснути `Add` для збереження.
   - Очікувано: автомобіль додано до Garage.
6. Перевірити запис у Garage.
   - Критерій успіху: у списку видно `Audi TT`.
   - Додаткова перевірка: пробіг `12000` видно для цього автомобіля, якщо поточний UI його відображає.

### Умови невдачі або зупинки

- Кнопка, поле чи потрібне значення відсутні в поточному UI.
- Форму не вдається зберегти.
- Після збереження в Garage не з’являється `Audi TT`.
- Якщо UI відрізняється від вимоги, зафіксувати спостережуваний факт як blocker; не вигадувати успішний результат і не оголошувати дефект без діагностики.

## Обмеження та невирішені питання

- Перевіряється лише гостьовий UI-сценарій додавання автомобіля.
- Локатори потрібно підтвердити за актуальним accessibility snapshot або locator picker перед написанням тесту.
- Вимога не визначає очікувану поведінку для порожнього чи некоректного пробігу, тому негативні перевірки валідації не включено.
- Якщо потрібно вимагати порожній Garage на старті, це має бути підтверджено окремо: вихідна вимога цього не задає.
